# Jellyfin on the NAS: performance and memory tuning

**Date:** 2026-09-07 · **Status:** implemented the same day (autonomous run, Philip away)

## Findings (read-only discovery)

| Item | Before |
|---|---|
| Host | Ugreen NAS, Intel Pentium Gold 8505 (Alder Lake, 6 threads, UHD Graphics w/ Quick Sync), 31 GB RAM, 3×7.2 TB RAID 5 ext4, 465 GB M.2 as **read-only SSD cache** (300 GB allocated) |
| Container | `jellyfin/jellyfin:latest` (10.11.11), hand-made in UGOS, `/dev/dri` passed, **no memory/CPU limit**, transcodes on the HDD pool |
| Jellyfin HW accel | QSV selected, HW *encoding* on, but **`HardwareDecodingCodecs` empty** → every transcode decoded in software |
| Tone mapping | `EnableTonemapping=false`, `EnableVppTonemapping=true` (correct: OpenCL mapping is unusable on this box, VPP works) |
| Low-power encoders | off — but this chip's HEVC encoder only exists as low-power (`vainfo`: HEVC EncSliceLP only) |
| Throttling / segment deletion | off (full-file transcodes written to HDD) |
| Trickplay | disabled per library; server options had HW off |
| Chapter images | off (kept off — heavy, little value) |
| Health | log clean, all scheduled tasks completed, 1.3 GB RSS after 13 days |

Measured with jellyfin-ffmpeg on a 4K HEVC 10-bit HDR remux → 1080p:

| Pipeline | fps |
|---|---|
| SW decode + QSV H.264 encode (old behaviour) | 65 (CPU saturated) |
| QSV decode + QSV H.264 encode | 173 |
| QSV decode + QSV HEVC low-power 10-bit | 178 |
| QSV decode + VPP tone-map HDR→SDR + H.264 LP | 109 |

## Changes

1. **encoding.xml**: `HardwareDecodingCodecs` = h264, hevc, mpeg2video, vc1, vp8, vp9, av1;
   `EnableIntelLowPowerH264HwEncoder`/`…Hevc…` = true; `EnableThrottling` = true
   (180 s); `EnableSegmentDeletion` = true (keep 720 s). Tone mapping left as VPP.
2. **system.xml TrickplayOptions**: HW acceleration + HW encoding + key-frame-only
   extraction on (NonBlocking, BelowNormal). Libraries Movies/Series:
   `EnableTrickplayImageExtraction` = true (generated by the nightly task, not
   during scans). Scrub previews appear as the task runs through the library.
3. **Container → compose project `nas/jellyfin/`**: pinned `10.11.11`, `/dev/dri`,
   same volumes/ports, `/cache/transcodes` on **tmpfs 6 GB** (no HDD writes while
   streaming), `mem_limit 5g`, `DOTNET_gcServer=0`, `DOTNET_GCHeapHardLimit=3 GiB`,
   `JELLYFIN_PublishedServerUrl`.
4. Backups of every edited file in `nas-apps/jellyfin/configurations/config/backup-2026-09-07/`.

## Deliberately not changed

- **SSD cache**: read-only cache of Volume 1 already accelerates the metadata/DB
  reads. Repurposing the M.2 as a dedicated volume for `nas-apps` would be faster
  still but destroys the cache — Philip's call, not an autonomous one.
- Chapter image extraction stays off. Real-time monitoring stays on (local disks).
- Discovery port stays `37359:7359/udp` as before (LAN auto-discovery would need
  host port 7359; nothing relied on it).
